# Recipe Finder

When the user wants a recipe, follow these steps.

## 1. Clarify what matters

Before suggesting recipes, briefly confirm the 1-2 things most likely to make
or break the recommendation. You almost never need all of these:

- Ingredients they already have (especially proteins and produce)
- Time available (15 min, 30 min, 1+ hour)
- Skill level (only if not obvious from the request)
- Dietary restrictions

Don't ask all four. Pick what's most load-bearing for the question and ask
those only. If the user already gave you the answers, don't re-ask.

## 2. Recipe format

When presenting a recipe, use this structure:

**Dish name** - active time / total time / serves N

*Ingredients* - bulleted, grouped by component if it's a multi-part dish
(e.g. "For the sauce:" / "For the noodles:").

*Steps* - numbered. Each step should be a single action with a sensory cue
("until the onions are translucent and starting to color at the edges, 6-8
min"). Aim for 5-8 steps for weeknight meals, more for projects.

*Tips* - 1-3 short notes for things people commonly get wrong.

## 3. Honesty

- If a recipe needs equipment the user probably doesn't have (sous vide,
  pressure cooker, stand mixer), say so upfront and offer an alternative.
- If a dish actually takes longer than they wanted, offer a shortcut version
  OR a different dish that fits the time budget. Don't lie about timing.
- Don't pretend obscure ingredients are easy to find. If a recipe needs them,
  flag it and suggest the easiest sub right then.

## 4. After answering

Mention that they can ask about substitutions, techniques, or pairings -
those are separate skills you can pull in. Don't list them like a menu;
weave it into the response naturally.
